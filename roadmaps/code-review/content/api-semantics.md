# Perguntas a Serem Feitas

- A API deve ser o menor possível, mas também o maior necessário?
- Há uma única maneira de fazer algo, ou várias opções?
- É consistente? Ele segue o princípio da surpresa mínima?
- Haverá uma separação limpa entre a API e os detalhes internos, sem que os detalhes internos invadan a API?
- Não haverão alterações quebrantes em partes visíveis para os usuários (classes de API, configuração, métricas, formatos de log, etc.)?
- Um novo API será geralmente útil e não muito específico para um único caso de uso?
