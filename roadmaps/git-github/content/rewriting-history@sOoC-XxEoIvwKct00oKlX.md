# Reescrevendo Histórico

Reescrever o histórico refere-se a operações do Git que alteram os commits existentes em vez de adicionar novos no topo, como modificar uma mensagem de commit ou rebase uma série de commits. Essas operações alteram hashes de commit, o que pode causar problemas para qualquer pessoa que já tenha uma cópia da história original. Por isso, reescrever o histórico geralmente é seguro em branches locais ou não compartilhados, mas arriscado em branches que outras pessoas estão usando ativamente.
